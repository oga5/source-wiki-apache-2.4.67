httpd-2.4.67

このシステムは何か

httpd-2.4.67 は、Apache HTTP Server のソースコードベースです。モジュール化されたアーキテクチャを採用しており、リクエスト処理、プロトコル制御、セキュリティ、キャッシュ、およびプラットフォーム固有の抽象化レイヤーを個別のモジュールとして実装しています。

アーキテクチャ概観

本システムは、コアエンジンと、それを拡張する多数のモジュール群で構成されています。

  • **コア**: リクエスト処理のライフサイクル、設定管理、およびマルチプロセッシング（MPM）の基盤を提供します。
  • **MPM**: OS に適した並行処理モデル（Event, Worker, Prefork 等）を選択・実装します。
  • **フィルタチェーン**: バケットブリゲード（apr_bucket_brigade）を介したストリーム処理パイプラインにより、データの加工・転送を行います。
  • **プロバイダーモデル**: 認証、認可、キャッシュ、ロック管理などの機能を抽象化し、バックエンド実装を疎結合に切り替え可能にしています。

主要モジュール

  • **server**: サーバーの起動、設定、MPM 管理の基盤。
  • **modules/http / modules/http2**: HTTP/1.1 および HTTP/2 プロトコルの実装。
  • **modules/aaa**: 認証・認可（AAA）フレームワーク。
  • **modules/cache**: コンテンツキャッシュおよび共有オブジェクトキャッシュ（socache）。
  • **modules/dav**: WebDAV プロトコルおよびリポジトリ管理。
  • **modules/proxy**: ロードバランサおよび各種プロトコルプロキシ。
  • **modules/ssl**: OpenSSL を用いたセキュア通信。
  • **modules/md**: ACME プロトコルによる証明書自動管理。

実行時ライフサイクル

1. **初期化**: main 関数から起動し、設定ファイルをパースして設定ツリーを構築。各モジュールの register_hooks が呼び出され、処理フェーズにハンドラが登録されます。 2. **MPM 起動**: 選択された MPM が子プロセス/スレッドを生成し、リスナーソケットを監視します。 3. **リクエスト処理**: 接続を受け入れると、フィルタチェーンを介してリクエストが解析され、適切なハンドラへディスパッチされます。 4. **終了**: シグナル受信により clean_child_exit 等が呼び出され、リソースのクリーンアップとプロセスの終了が行われます。

中核データ構造

  • **request_rec**: リクエストのライフサイクル全体を管理するコンテキスト。
  • **conn_rec**: 接続ごとの状態を保持。
  • **ap_filter_t**: フィルタチェーンの各ノード。
  • **apr_bucket_brigade**: フィルタ間を流れるデータストリームのコンテナ。
  • **module**: モジュールのエントリポイントと設定を保持する構造体。
  • **ap_conf_vector_t**: モジュールごとの設定情報を格納するベクトル。

横断的トピック

  • **メモリ管理**: apr_pool_t を用いた階層的なメモリ管理により、リクエストや接続の終了時にリソースを一括解放します。
  • **フック機構**: AP_IMPLEMENT_HOOK_* マクロにより、モジュール間で疎結合な処理の挿入を可能にします。
  • **共有メモリ管理**: slotmem や socache を通じ、プロセス間での状態共有（セッションキャッシュやロードバランサのステータス）を実現します。
  • **プロトコル抽象化**: apr_off_t や apr_status_t を用いたプラットフォーム非依存のデータ型管理。

推奨読書順

1. include/httpd.h (基本構造の理解) 2. server/config.c (設定とモジュール管理) 3. server/mpm/event/event.c (並行処理モデルの理解) 4. modules/http/http_request.c (リクエスト処理のライフサイクル) 5. include/util_filter.h (フィルタチェーンの仕組み) 6. modules/aaa/mod_authn_core.c (プロバイダーフレームワークの例)
