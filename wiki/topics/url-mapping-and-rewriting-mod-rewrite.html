URL Mapping and Rewriting (mod_rewrite)

概念

**URL Mapping and Rewriting** は、Apache HTTP Server が受信したリクエスト URL を、サーバー上の物理的なファイルパスや別の URL へ変換・再マッピングする仕組みです。この処理は主に module:modules/mappers に属するモジュール群（mod_alias や mod_rewrite など）によって行われます。

なぜ重要か

クライアントがアクセスする公開用の論理 URL と、サーバー内部の物理的なリソース配置を切り離すために不可欠です。これにより、Web サイトのディレクトリ構造を変更することなく URL を維持したり、特定のパターンに合致するリクエストを別のハンドラーや外部 URL へリダイレクトしたりする柔軟な制御が可能になります。

関与するモジュール

  • module:modules/mappers

主要エンティティ

  • **symbol:modules/mappers/mod_alias.c#translate_alias_redir**

    • mod_alias モジュールにおける主要な変換関数です。リクエスト情報（request_rec *r）を受け取り、エイリアスやリダイレクトの適用を試みます。

  • **symbol:modules/mappers/mod_rewrite.c#command_table**

    • mod_rewrite モジュールが提供する設定ディレクティブ（RewriteRule や RewriteCond など）を定義するコマンドテーブルです。

エンドツーエンドの流れ

現時点では、リクエストが入力されてから書き換えルールが評価され、最終的なファイルパスやリダイレクト先に決定されるまでの詳細なエンドツーエンドの実行フローは完全には解析されておらず、不明です。

ただし、mod_alias においては以下の部分的な流れが確認されています。 1. リクエスト処理フェーズにおいて translate_alias_redir が呼び出される。 2. ap_get_module_config を用いてモジュール設定を取得する。 3. try_alias、try_alias_list、try_redirect などの内部関数を呼び出し、設定されたルールに合致するかを判定する。 4. 必要に応じて ap_construct_url を使用して新しい URL を構築する。

重要な不変条件

現時点では、URL 書き換え処理における詳細な不変条件（書き換えループの防止策、メモリ確保のライフサイクル、スレッド安全性など）は解析されておらず、不明です。

よくある落とし穴

現時点では、mod_alias と mod_rewrite の適用順序の競合や、無限ループの発生条件など、具体的な落とし穴に関する詳細な情報は解析されておらず、不明です。
