WebDAV Repository and Locking (mod_dav)

概念

mod_dav における WebDAV Repository and Locking は、WebDAV（Web-based Distributed Authoring and Versioning）プロトコルで規定されているリソースのプロパティ管理および排他制御（ロック）をサポートするための仕組みです。これらは、ファイルシステムなどのバックエンドストレージと連携し、複数クライアントによる同時編集時の競合防止や、リソースに付随するメタデータの永続化を提供します。

なぜ重要か

WebDAV環境において、リソースの整合性を保つためのロック管理や、リソース固有のメタデータ（プロパティ）を管理することは不可欠です。mod_dav は、ロックデータベース（DBM）へのアクセス状態を管理する構造体や、UUIDベースのロックトークン、プロパティデータベースを抽象化したコンテキスト構造体を提供することで、バックエンドの実装に依存しない一貫した操作を可能にします。

関与するモジュール

  • module:modules/dav/fs

主要エンティティ

  • **symbol:modules/dav/fs/lock.c#dav_lock_private**: ロックデータベース（DBM）内での検索や識別に使用される、ロックに関連付けられたプライベートなキー情報（apr_datum_t key）を保持する構造体。
  • **symbol:modules/dav/fs/lock.c#dav_lockdb_private**: ファイルシステムベースのDAVロックデータベース（DBM）へのアクセスに必要な状態情報（リクエスト、メモリプール、ロックDBパス、オープン状態、DBハンドルなど）を保持するプライベート構造体。
  • **symbol:modules/dav/fs/lock.c#dav_locktoken**: WebDAVロックを一意に識別するためのUUID（apr_uuid_t uuid）を保持するラッパー構造体。
  • **symbol:modules/dav/main/mod_dav.h#dav_propdb**: WebDAVプロパティデータベースへのアクセスおよび操作（ライブプロパティの検索やプロバイダーの特定など）を管理するためのコンテキスト構造体。

エンドツーエンドの流れ

提供されたソースコードの断片からは、リクエストの受信からロック・プロパティ操作の完了に至る完全なエンドツーエンドの制御フローは完全には明らかになっていません（未検証）。ただし、部分的な処理の流れとして以下が確認できます。

1. **プロパティ操作のライフサイクル**: リクエスト処理フロー（mod_dav.c）やライブプロパティ検索時（props.c）において、dav_propdb が初期化され、プロパティ操作のコンテキストとして保持されます。操作終了時には dav_close_propdb を通じて明示的にクローズされ、リソースが解放されます。 2. **ロックデータベース操作と遅延オープン**: ロックの読み込みや保存の際、dav_lockdb_private を通じてデータベースのパスやハンドルが参照されます。データベースの実際のオープン処理は、初回アクセス時まで遅延される制御（遅延オープン）が行われます。ロックの識別には dav_locktoken（UUID）が使用され、DBMへのアクセスキーとして dav_lock_private の key が利用されます。

重要な不変条件

  • **dav_lockdb_private の状態整合性**:

    • db メンバが非NULLである場合、データベースは正常に開かれている必要があります。また、メモリ管理は pool メンバ（通常は r->pool に関連付けられたもの）に紐付いて行われる必要があります。

  • **dav_propdb のクローズ義務**:

    • プロパティ操作のライフサイクル（validate/exec/commit/rollback）において一貫したコンテキストとして保持され、操作終了時には必ず dav_close_propdb による明示的なクローズが必要です。

  • **dav_locktoken の一意性**:

    • 内部に保持する apr_uuid_t を介して一意性が保証される必要があります。

よくある落とし穴

  • **未オープン状態でのDB操作**:

    • dav_lockdb_private において、db がNULLの状態でデータベース操作を試みると失敗します。また、読み取り専用で開かれているデータベースに対して書き込み操作を行うとエラーになります。

  • **プロバイダー未定義や接続失敗**:

    • dav_propdb の利用時、プロバイダーが未定義の場合やデータベースへの接続が確立できない場合、プロパティ操作は実行できずエラーとなります。

  • **DBMデータの破損**:

    • dav_lock_private が保持する key が指すDBM内のデータが破損している場合、後続のデータベース操作が失敗する可能性があります。
