Shared Object Caching (socache) Architecture

概念

Shared Object Caching (socache) は、SSLセッションや認証資格情報などの小規模オブジェクトをキャッシュするためのプロバイダーベースのアーキテクチャです。このアーキテクチャは、具体的なキャッシュストレージの実装（共有メモリ、Memcached、Redisなど）を抽象化し、共通のインターフェースを提供します。各バックエンド実装は、個別のキャッシュインスタンスの状態を管理するために、不透明な（opaque）構造体である ap_socache_instance_t を使用します。

なぜ重要か

socache アーキテクチャが重要な理由は、キャッシュを利用するモジュール（認証モジュールやSSLモジュールなど）に対して、ストレージの具体的な実装に依存しない一貫したAPIを提供できる点にあります。これにより、システムの要件や規模に応じて、共有メモリベースの高速なローカルキャッシュ（shmcb）や、外部の分散キャッシュ（Memcached、Redis）を柔軟に切り替えることが可能になります。

関与するモジュール

  • module:include (共通インターフェース ap_socache.h の定義)
  • module:modules/cache (具体的なキャッシュプロバイダーの実装。mod_socache_shmcb、mod_socache_memcache、mod_socache_redis など)

主要エンティティ

  • **symbol:include/ap_socache.h#ap_socache_instance_t**:

    • 各キャッシュプロバイダー実装において、個別のキャッシュインスタンスの状態を保持するための不透明な（opaque）構造体です。呼び出し側は内部構造を直接操作せず、ポインタを介して間接的に操作します。

  • **symbol:modules/cache/mod_socache_shmcb.c#socache_shmcb_store**:

    • 共有メモリベースの循環バッファ（SHMCB）キャッシュにデータを保存する具体的な関数です。ap_socache_provider_t 構造体を通じて呼び出されます。

エンドツーエンドの流れ

1. **インスタンスの生成と初期化**: 呼び出し側モジュールは、キャッシュプロバイダーの create メソッドを呼び出して ap_socache_instance_t を生成し、その後 init メソッドを呼び出して初期化します。 2. **データの保存**: データの保存要求が発生すると、プロバイダーの store メソッド（例: socache_shmcb_store）が呼び出されます。 3. **SHMCBにおける保存処理**: socache_shmcb_store では、キー（id）に基づいて対象のサブキャッシュを特定し、既存の同一IDエントリを削除（置換準備）した上で、新しいデータをサブキャッシュに書き込みます。書き込み成功時には統計カウンタが更新されます。

*注意: 呼び出し側モジュール（認証モジュールなど）における具体的な初期化タイミングや、データの取得（retrieve）・削除（remove）を含む完全なエンドツーエンドのライフサイクル全体の流れは、提供された情報からは完全には明らかになっていません。*

重要な不変条件

  • **初期化の必須性**:

    • ap_socache_instance_t は、プロバイダーの create メソッドで生成された後、init メソッドが呼び出されるまでキャッシュ操作に使用することはできません。

  • **キーの最小長**:

    • socache_shmcb_store を使用する場合、キャッシュキーの長さ（idlen）は **4バイト以上** でなければなりません。

  • **排他制御の責任**:

    • socache_shmcb_store 自体は排他制御（ロック）を行いません。呼び出し側で適切なロック管理を行う必要があります。

よくある落とし穴

  • **スレッドセーフティの欠如**:

    • mod_socache_shmcb は AP_SOCACHE_FLAG_NOTMPSAFE フラグが示す通り、スレッドセーフではありません。呼び出し側で適切な同期を行わずにマルチスレッド環境からアクセスすると、データ競合が発生する恐れがあります。

  • **キー長不足によるエラー**:

    • idlen が 4 未満のキーを渡すと、socache_shmcb_store は APR_EINVAL を返して保存処理を中止します。

  • **オーバーフローのリスク**:

    • socache_shmcb_store 内部のサイズ計算には unsigned int が使用されているため、極めて大きなキャッシュサイズを設定した場合には、整数オーバーフローが発生するリスクがあります。
