Dynamic Module Loading and Configuration Parsing

概念

Apache HTTP Server は、起動時または再起動時に設定ファイルを解析し、必要に応じて共有オブジェクト（DSO）からモジュールを動的にロードします。 設定ファイルの内容は、メモリ上に階層的な設定ツリー（ap_directive_t）として構築されます。また、LoadModule ディレクティブが検出されると、mod_so モジュールを介して動的に共有オブジェクトがプロセス空間にロードされ、Apache のモジュール構造体として統合されます。

なぜ重要か

この仕組みにより、Apache はコア機能を最小限に抑えつつ、必要に応じて機能を動的に拡張できます。また、設定ファイルをパースして構造化されたツリーにすることで、各モジュールが自身のディレクティブを効率的に処理し、サーバー設定（create_server_config などで生成される設定ベクトル）を適用することが可能になります。

関与するモジュール

  • module:include (設定ツリーのデータ構造定義)
  • module:modules/core (動的モジュールロードを担う mod_so.c を含む)
  • module:server (サーバー設定の生成や設定解析のコアロジックを含む)

主要エンティティ

  • **symbol:include/util_cfgtree.h#ap_directive_t**: 設定ファイルをメモリ上に階層構造（設定ツリー）として表現するためのノード構造体。
  • **symbol:modules/core/mod_so.c#load_module**: LoadModule ディレクティブのハンドラとして機能し、DSO を動的にロードして Apache のグローバルモジュールリストに統合する関数。
  • **symbol:server/config.c#create_server_config**: サーバー設定ベクトル（ap_conf_vector_t）を生成する静的関数。

エンドツーエンドの流れ

1. **設定ファイルの解析とツリー構築**: サーバー起動時、設定ファイルが読み込まれ、各ディレクティブが ap_directive_t ノードとして設定ツリーに挿入されます。 2. **動的モジュールのロード**: 設定解析中に LoadModule ディレクティブが検出されると、load_module が呼び出されます。

  • load_module は、指定された共有オブジェクト（DSO）をプロセス空間にロードし、シンボル（module 構造体）を解決します。
  • ロードされたモジュールはグローバルモジュールリストに追加され、ap_single_module_configure によって初期化されます。

    • 3. **サーバー設定の生成**: サーバー設定の初期化フェーズ（init_server_config）において、create_server_config が呼び出され、各モジュールの設定を保持するための設定ベクトルが生成されます。

*注意: 設定ツリーの構築から各モジュールへの設定適用の詳細なエンドツーエンドの完全な制御フロー、および create_server_config の内部アルゴリズムの詳細は、提供された情報からは完全には明らかになっていません。*

重要な不変条件

  • **モジュールの重複防止**: ロード対象のモジュールは、既にロードされているモジュールや静的リンクされたモジュールと重複してはなりません（load_module 内でチェックされます）。
  • **モジュールの有効性**: ロードされた DSO は、MODULE_MAGIC_COOKIE を保持する有効な Apache モジュール構造体でなければなりません。
  • **設定ツリーの順序性**: ap_directive_t は設定ファイルに記述された順序を保持します。ただし、閉じタグ（</Directory> など）はツリーのノードとしては保存されません。

よくある落とし穴

  • **シンボル解決の失敗**: LoadModule で指定されたモジュール名に対応するシンボルが DSO 内に存在しない場合、ロードは失敗します。
  • **バージョン不整合**: DSO の magic 番号がサーバーの MODULE_MAGIC_COOKIE と一致しない場合、互換性エラーとしてロードが拒否されます。
  • **動的設定変更の制限**: ap_directive_t による設定ツリーは主にサーバー起動時の設定読み込みフェーズに特化しており、実行時の動的な設定変更には別のメカニズムが関与する場合があります。

次に読む場所

  • include/util_cfgtree.h (設定ツリー構造体 ap_directive_t の定義)
  • modules/core/mod_so.c (動的モジュールロード load_module の実装)
  • server/config.c (サーバー設定生成 create_server_config の実装)
