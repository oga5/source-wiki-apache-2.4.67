Authentication and Authorization Provider Architecture

概念

Authentication and Authorization Provider Architecture（認証・認可プロバイダーアーキテクチャ）は、Apache HTTP Server（httpd）における認証（Authentication: authn）と認可（Authorization: authz）の処理をモジュール化し、柔軟に拡張可能にするための共通フレームワークです。 このアーキテクチャでは、認証方式（例：Basic認証）を提供するフロントエンドモジュールと、実際のユーザー資格情報を検証するバックエンドプロバイダー（例：ファイル、データベース）、およびアクセス制御ルールを評価する認可プロバイダーが明確に分離されています。

なぜ重要か

このアーキテクチャにより、認証スキーム（どのように資格情報を送るか）と、認証データソース（どこで資格情報を検証するか）が疎結合になります。開発者は既存のBasic認証などの仕組みを再利用しつつ、独自のユーザーデータベースに対応した新しい認証プロバイダーや、複雑なアクセス制御ルールを持つ認可プロバイダーを個別に実装・追加できます。

関与するモジュール

  • module:include (include/mod_auth.h): 認証および認可プロバイダーが共有する共通のデータ構造やAPI定義を提供します。
  • module:modules/aaa (modules/aaa/mod_auth_basic.c, modules/aaa/mod_authn_core.c, modules/aaa/mod_authz_core.c): 認証・認可のコアロジックと、Basic認証などの具体的な認証プロトコルハンドラを実装します。

主要エンティティ

  • **authn_provider (構造体 / include/mod_auth.h)**: 認証プロバイダー（例：パスワードの検証関数など）が実装すべきインターフェースを定義します。
  • **mod_auth_basic.c**: HTTP Basic認証スキームを処理するフロントエンドモジュール。クライアントから送られた資格情報を抽出し、登録された認証プロバイダーに検証を委ねます。
  • **mod_authn_core.c**: 認証プロバイダーの登録（ap_register_provider）および管理を行うコアモジュール。
  • **mod_authz_core.c**: 認可プロバイダーの管理と、Require ディレクティブ（および <RequireAll> などのコンテナ）によるアクセス制御ルールの評価を行うコアモジュール。

エンドツーエンドの流れ

1. **リクエストの受信と認証ハンドラの起動**: クライアントからリクエストが到達すると、mod_auth_basic.c などの認証ハンドラが起動します。 2. **認証プロバイダーの呼び出し**: mod_auth_basic は、設定された認証プロバイダー（mod_authn_core を介して登録された file や dbm など）を呼び出し、ユーザー名とパスワードの検証を要求します。 3. **認可の評価**: 認証が成功すると、mod_authz_core.c が Require ディレクティブに基づいて登録済みの認可プロバイダーを呼び出し、当該ユーザーがリソースへのアクセス権限を持っているかを判定します。

*注意: 詳細な関数呼び出しシーケンスや内部状態遷移の完全なエンドツーエンドフローは、提供された静的ソースコードのメタデータからは完全には特定されていません。*

重要な不変条件

  • **認証と認可の分離**: 認証プロバイダーは「ユーザーが誰であるか（および資格情報が正しいか）」の検証のみを担当し、認可プロバイダーは「そのユーザーがリソースへのアクセスを許可されているか」の判定のみを担当します。
  • **プロバイダー登録の義務**: すべての認証・認可プロバイダーは、コア（mod_authn_core / mod_authz_core）が提供する登録APIを介して、適切なグループ名（例：AUTHN_PROVIDER_GROUP）で登録されていなければ、フロントエンドから参照できません。

*注意: 実行時における詳細な不変条件やスレッドセーフ性に関する制約は、現時点では完全には判明していません。*

よくある落とし穴

  • **プロバイダーのロード忘れ**: AuthBasicProvider ディレクティブで特定のプロバイダー（例：file）を指定しているにもかかわらず、対応するプロバイダーモジュール（mod_authn_file など）がロードされていない場合、認証エラーやサーバー起動エラーが発生します。
  • **認可コンテナの評価順序**: mod_authz_core における <RequireAll> や <RequireAny> などの論理コンテナのネスト設定を誤ると、意図しないアクセス許可や拒否が発生する可能性があります。

次に読む場所

  • include/mod_auth.h — 認証・認可プロバイダーの共通インターフェース定義
  • modules/aaa/mod_authn_core.c — 認証プロバイダーの登録とコア管理ロジック
  • modules/aaa/mod_authz_core.c — 認可プロバイダーの登録と Require ルールの評価ロジック
  • modules/aaa/mod_auth_basic.c — Basic認証スキームの実装例
