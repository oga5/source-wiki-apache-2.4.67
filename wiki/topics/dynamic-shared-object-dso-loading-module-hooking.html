Dynamic Shared Object (DSO) Loading & Module Hooking

概念

Apache HTTP Serverは、実行時に共有オブジェクト（DSO）を動的にロードし、サーバーの機能を拡張する仕組みを提供しています。mod_so モジュール（modules/core/mod_so.c）がこの動的ロードの中心的な役割を担い、ロードされたモジュールはApacheのグローバルモジュールリストに統合され、フック（Hook）登録システムを通じてリクエスト処理などの各フェーズに処理をディスパッチします。

なぜ重要か

DSOロード機能により、Apacheのコアバイナリを再コンパイルすることなく、必要に応じてサードパーティ製モジュールや追加機能を動的にロード・アンロードできます。これにより、メモリ使用量の最適化や、柔軟なサーバー構成の変更が可能となります。

関与するモジュール

提供されたコンテキストに基づき、以下のモジュールが関与しています。

  • module:include（フック定義やコアAPIヘッダーを提供）
  • module:modules/core（DSOロードの実装である mod_so.c を含む）
  • module:server（設定管理やコア設定処理 config.c を含む）

主要エンティティ

  • **symbol:modules/core/mod_so.c#load_module**: LoadModule ディレクティブのハンドラ。DSOファイルをロードし、モジュール構造体を検証してApacheに統合します。
  • **symbol:modules/core/mod_so.c#ap_find_loaded_module_symbol**: 指定された名前を持つロード済みモジュールの構造体ポインタ（module *）を検索して返します。
  • **symbol:include/ap_hooks.h#AP_IMPLEMENT_HOOK_RUN_ALL**: フックの実装マクロ（詳細な実装は提供されたコンテキストからは未詳ですが、フック実行を制御します）。

エンドツーエンドの流れ

1. **設定の解析とロードのトリガー**: 設定ファイル中の LoadModule ディレクティブにより、symbol:modules/core/mod_so.c#load_module が呼び出されます。 2. **重複チェック**: 既にロード済みのモジュールリストや静的リンク済みモジュールリストを走査し、名前の衝突がないか確認します。 3. **DSOのロードとシンボル解決**: dso_load（内部関数）を呼び出して共有オブジェクトをプロセス空間にマッピングし、apr_dso_sym を用いてモジュール構造体（module）のシンボルを取得します。 4. **検証と統合**: 取得したモジュールの magic フィールドが MODULE_MAGIC_COOKIE と一致するか検証し、ap_add_loaded_module を介してグローバルモジュールリストへ追加します。 5. **クリーンアップと初期化**: サーバー終了時に unload_module が実行されるよう apr_pool_cleanup_register に登録し、ap_single_module_configure でモジュールの設定を初期化します。 6. **モジュールの検索**: 必要に応じて、他のモジュールやコアシステムから symbol:modules/core/mod_so.c#ap_find_loaded_module_symbol を呼び出し、ロードされたモジュールの構造体ポインタを取得します。

*注意: include/ap_hooks.h や server/config.c における具体的なフック登録や、リクエスト処理フェーズへのディスパッチに関する詳細なエンドツーエンドの流れは、提供されたコンテキストからは完全には明らかになっていません。*

重要な不変条件

  • **モジュールの重複禁止**: ロード対象のモジュールは、既にロードされているモジュールや静的にリンクされているモジュールと名前が重複してはなりません（symbol:modules/core/mod_so.c#load_module 内で検証）。
  • **ABI互換性の保証**: ロードされたDSOの magic フィールドは、Apacheコアの MODULE_MAGIC_COOKIE と一致しなければなりません。
  • **検索時の有効性**: symbol:modules/core/mod_so.c#ap_find_loaded_module_symbol を呼び出す際、サーバー設定 server_rec が有効であり、so_server_conf およびその loaded_modules 配列が初期化済みでなければなりません。

よくある落とし穴

  • **シンボル名の衝突**: 静的リンクされたモジュールと同名のDSOをロードしようとすると、ロード処理がエラーを返して失敗します。
  • **バージョン不整合（Magic Cookieの不一致）**: 異なるバージョンのApache向けにビルドされたDSOをロードしようとすると、MODULE_MAGIC_COOKIE の検証に失敗し、互換性エラーとなります。
  • **初期化未完了時の検索**: サーバー設定（server_rec）が正しく初期化される前に symbol:modules/core/mod_so.c#ap_find_loaded_module_symbol を呼び出すと、ap_get_module_config の結果が不正になり、セグメンテーションフォールトなどの予期せぬ動作を引き起こす可能性があります。

次に読む場所

  • include/ap_hooks.h（フックの実装マクロや登録機構の確認）
  • modules/core/mod_so.c（DSOロードおよびモジュール検索の具体的な実装）
  • server/config.c（モジュール設定の適用や初期化プロセスの確認）
