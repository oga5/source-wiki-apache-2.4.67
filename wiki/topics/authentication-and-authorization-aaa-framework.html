Authentication and Authorization (AAA) Framework

概念

Authentication and Authorization (AAA) Framework は、Apache HTTP Server においてクライアントの識別（認証）とリソースへのアクセス制御（認可）をモジュール化された構造で提供する仕組みです。

提供されたモジュール群（mod_auth_basic、mod_authn_core、mod_authz_core）は、認証方式の仲介、ディレクトリ単位の設定管理、および認可処理を協調して行います。

なぜ重要か

Apache HTTP Server 2.4 における AAA フレームワークは、認証ロジック（Basic 認証など）と実際のユーザーデータベース（認証プロバイダー）を分離し、さらに認可ロジックをコア機能として統合することで、柔軟で拡張性の高いアクセス制御を実現しています。

例えば、mod_auth_basic は認証の「仲介」に特化し、実際のパスワード検証は登録されたプロバイダーに委譲します。これにより、認証方式とバックエンドデータベースの組み合わせを自由に変更できます。

関与するモジュール

  • module:modules/aaa
  • modules/aaa/mod_auth_basic.c: Basic 認証スキームの仲介を担当。
  • modules/aaa/mod_authn_core.c: 認証コア設定（ディレクトリ単位の設定など）の管理を担当。
  • modules/aaa/mod_authz_core.c: 認可処理のコアロジックを担当。

主要エンティティ

  • symbol:modules/aaa/mod_auth_basic.c#authenticate_basic_user: HTTP Basic 認証において、クライアントの資格情報を抽出し、設定された認証プロバイダーを順次呼び出して検証を仲介する関数。
  • symbol:modules/aaa/mod_authn_core.c#create_authn_core_dir_config: ディレクトリ単位の認証設定（AuthType や AuthName など）を保持する authn_core_dir_conf 構造体をメモリ上に確保・初期化する関数。
  • symbol:modules/aaa/mod_authz_core.c#authorize_user: ユーザーの認可処理を行う関数（詳細な内部アルゴリズムは未解析）。

エンドツーエンドの流れ

提供されたソースコード情報からは、認証から認可に至る完全なエンドツーエンドの制御フローの全容は完全には明らかになっていません。現時点で判明している部分的な流れは以下の通りです。

1. **設定フェーズ**:

  • Apache の起動・設定読み込み時に、create_authn_core_dir_config が呼び出され、ディレクトリ単位の認証設定構造体（authn_core_dir_conf）が apr_pcalloc により初期化されます。

    • 2. **認証フェーズ**:

  • リクエスト処理中、ap_hook_check_authn に登録された authenticate_basic_user が呼び出されます。
  • authenticate_basic_user は、リクエストの AuthType が Basic であることを確認し、get_basic_auth を介して Authorization ヘッダーからユーザー名とパスワードを抽出します。
  • 設定された認証プロバイダー（mod_authn_core 等で管理されるプロバイダーリスト）を走査し、各プロバイダーの check_password や get_realm_hash を呼び出して資格情報を検証します。
  • 認証結果（OK、DECLINED、HTTP_UNAUTHORIZED など）を返します。

    • 3. **認可フェーズ**:

  • 認証成功後、mod_authz_core の authorize_user が呼び出され、内部で authorize_user_core を呼び出してユーザーのアクセス権限を検証します（詳細な評価フローは未解析）。

重要な不変条件

  • **Basic 認証の前提条件**: authenticate_basic_user が正常に動作するためには、AuthType が Basic に設定され、かつ AuthName が設定されている必要があります。AuthName が未設定の場合、処理は HTTP_INTERNAL_SERVER_ERROR を返します。
  • **設定の初期化**: create_authn_core_dir_config によって生成される authn_core_dir_conf 構造体は、apr_pcalloc を使用してゼロクリアされた状態で確保されることが保証されます。
  • **権限委譲の制御**: authoritative 設定が有効な場合、認証プロバイダーでの認証失敗は即座に HTTP_UNAUTHORIZED を返します。無効な場合は DECLINED を返し、後続の認証モジュールへ処理を委譲します。

よくある落とし穴

  • **AuthName の指定漏れ**: AuthName が設定ファイルで定義されていない場合、Basic 認証処理中に HTTP_INTERNAL_SERVER_ERROR が発生します。
  • **プロバイダーの未ロード/未設定**: 適切な認証プロバイダーがロードされていない、または設定されていない場合、認証の仲介処理は失敗し、HTTP_INTERNAL_SERVER_ERROR を返す原因となります。
  • **認可ロジックの未解析**: authorize_user の詳細な前提条件や失敗モードは現時点で未解析であるため、認可フェーズにおける不変条件の不一致による予期せぬアクセス拒否に注意する必要があります。
