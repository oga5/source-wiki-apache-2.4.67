HTTP/2 Protocol Engine (mod_http2)

概念

mod_http2 は、Apache HTTP Server において HTTP/2 プロトコル通信を処理するエンジンです。HTTP/2 の特徴である単一の接続上での複数ストリームの多重化（マルチプレクシング）を実現するため、セッション管理（h2_session）、マルチプレクサ（h2_mplx）、ストリーム制御（h2_stream）、およびスレッド間でデータを安全に転送するためのバケットビーム（h2_bucket_beam）などのコンポーネントが協調して動作します。

なぜ重要か

HTTP/2 は、従来の HTTP/1.1 と異なり、単一の TCP コネクション上で複数のリクエストとレスポンスを非同期に並行処理します。これを効率的かつ安全に実現するためには、接続を管理するメインスレッドと、各ストリームを処理するスレッドとの間で、メモリ管理やデータ転送を厳密に制御する必要があります。mod_http2 は、バケットビームによる効率的なデータ転送や、メモリ不足（OOM）時の安全なプロセス終了などを提供し、高パフォーマンスで堅牢な HTTP/2 通信を支えています。

関与するモジュール

  • module:modules/http2

主要エンティティ

提供されたソースコードおよびシンボル情報に基づく主要なエンティティは以下の通りです。

  • **h2_session_create** (modules/http2/h2_session.c):

    • HTTP/2 セッションを生成・初期化します。セッションの確立時に呼び出され、関連する I/O やマルチプレクサ、ストリームなどの初期化を行います。

  • **h2_stream_prepare_processing** (modules/http2/h2_stream.c):

    • ストリームの処理が開始される直前に呼び出され、入力データの受け渡しに必要な「入力ビーム」の構築が必要かどうかを判定して初期化を行います。

  • **h2_beam_create** (modules/http2/h2_bucket_beam.c):

    • コネクションとストリームスレッド間でデータを転送するためのカスタムバケットビーム（h2_bucket_beam）を生成します。

  • **abort_on_oom** (modules/http2/h2_mplx.c):

    • メモリ割り当て失敗（OOM）が発生した際に、プロセスを安全かつ強制的に終了させるためのコールバック関数です。

エンドツーエンドの流れ

提供された情報からは、詳細なエンドツーエンドの全体フローは完全には明らかになっていませんが、部分的なデータおよび処理の流れは以下の通りです。

1. **セッションの生成**: 接続のセットアップ（h2_c1_setup）の過程で h2_session_create が呼び出され、HTTP/2 セッションが生成されます。この中で、I/O の初期化（h2_c1_io_init）やマルチプレクサの生成（h2_mplx_c1_create）などが行われます。 2. **ストリーム処理の準備**: マルチプレクサ（h2_mplx.c）から h2_stream_prepare_processing が呼び出され、ストリームの処理開始直前に遅延初期化が実行されます。 3. **入力ビームのセットアップ**: ストリームの入力がまだ閉じられていない場合、stream_setup_input を経由して h2_beam_create が呼び出され、データ転送用のバケットビームが構築されます。

※ セッション確立からリクエスト受信、レスポンス送信、セッション切断に至る完全なエンドツーエンドのライフサイクルは、現時点では未解析です。

重要な不変条件

  • **入力ビームの条件付き初期化**:

    • h2_stream_prepare_processing において、ストリームの input_closed フラグが偽（入力がまだ閉じられていない）である場合のみ、stream_setup_input を呼び出して入力ビームをセットアップします。すでに閉じられている場合はセットアップをスキップします。

  • **OOM 時のプロセス終了**:

    • メモリプール管理構造体（apr_pool_t）に abort_on_oom が登録されている場合、メモリ不足が発生すると ap_abort_on_oom() を介して確実にプロセスが終了され、不安定な状態でのメモリ操作を防止します。

※ その他のセッション状態遷移や、マルチプレクサにおけるスレッド間の同期に関する不変条件は、現時点では未解析です。

よくある落とし穴

  • **同名関数による競合**:

    • abort_on_oom は apr_pool_abort_set に登録して使用されますが、support/passwd_common.h など他のソースファイルでも同名の関数が定義されている可能性があり、リンク時の重複定義やスコープの混同に注意する必要があります。

  • **遅延初期化のタイミング**:

    • h2_stream_prepare_processing はストリーム処理開始直前の特定のタイミングで呼び出される設計（遅延初期化）となっています。この呼び出しタイミングや input_closed フラグの状態管理を誤ると、必要な入力ビームが構築されず、データ転送が正常に行われない可能性があります。
