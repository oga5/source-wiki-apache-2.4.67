Managed Domains and ACME Integration (mod_md)

概念

mod_md (Managed Domains) は、Apache HTTP Server において SSL/TLS 証明書の自動管理を行うための仕組みです。ACME (Automated Certificate Management Environment) プロトコルを用いた証明書の自動プロビジョニングや更新、およびそれらに関連するドメイン設定、秘密鍵、証明書チェーン、チャレンジデータなどの永続化データをストレージ層から抽象化して管理する機能を提供します。

なぜ重要か

手動による SSL/TLS 証明書の取得・更新作業を自動化し、管理コストと証明書の期限切れリスクを削減するために重要です。mod_md は、ACME クライアントとしての初期化処理や、ファイルシステムなどの具体的な保存先に依存しないストレージ抽象化レイヤーを提供することで、安全かつ統一的なデータアクセスを実現します。

関与するモジュール

  • module:modules/md

主要エンティティ

  • **symbol:modules/md/md_acme.c#md_acme_init**: ACME モジュールの初期化を行う関数。製品名（base_product）の設定や、必要に応じた暗号化ライブラリの初期化（md_crypt_init）を実行します。
  • **symbol:modules/md/md_store.c#md_store_load**: ストレージ層から特定のドメイン関連データ（アカウント鍵、チャレンジデータ、JSON設定、証明書など）を読み込むための汎用インターフェース。具体的なストレージ実装（md_store_fs.c など）へ処理を委譲します。

エンドツーエンドの流れ

提供された情報からは、ACME プロトコルを用いた証明書の自動申請・更新・適用に至る完全なエンドツーエンドのライフサイクルの流れはまだ完全には明らかになっていません。

現時点で判明している部分的な流れは以下の通りです：

1. **モジュールの初期化**: Apache の起動フェーズ（modules/md/mod_md.c）において md_acme_init が呼び出され、製品識別子の登録および暗号化サブシステムの初期化が行われます。 2. **データのロード**: 実行時や設定ロード時に、アカウント管理（md_acme_acct.c）、チャレンジ認証（md_acme_authz.c）、設定管理（md_reg.c）などの各コンポーネントが md_store_load を呼び出し、必要な鍵や設定データをストレージから読み込みます。

重要な不変条件

  • **初期化の一貫性**: md_acme_init はモジュール初期化フェーズで一度だけ呼び出されることを想定しており、渡された製品名 base は静的変数 base_product にグローバルに保持されます。
  • **ストレージハンドラの有効性**: md_store_load を呼び出す際、store 引数は有効な md_store_t 構造体であり、その内部の load 関数ポインタが適切に初期化されていなければなりません。
  • **メモリプール依存性**: ロードされたデータの生存期間は、md_store_load に渡された apr_pool_t のライフサイクルに拘束されます。

よくある落とし穴

  • **未初期化ポインタによるクラッシュ**: md_store_t 構造体やその load 関数ポインタが NULL の状態で md_store_load を呼び出すと、セグメンテーションフォールトが発生する可能性があります。
  • **メモリ管理の誤り**: データのロードに使用する apr_pool_t の生存期間が不適切である場合、メモリリークや解放済みメモリへのアクセス（ダングリングポインタ）が発生する危険性があります。
  • **暗号化初期化エラー**: md_acme_init の呼び出し時に init_ssl を有効にした場合、内部の md_crypt_init が失敗すると初期化処理全体が失敗します。

次に読む場所

  • modules/md/md_acme.c (ACME プロトコルの初期化と処理)
  • modules/md/md_store.c (ストレージ抽象化インターフェースの実装)
  • modules/md/mod_md.c (モジュールのエントリーポイントと初期化の統合)
