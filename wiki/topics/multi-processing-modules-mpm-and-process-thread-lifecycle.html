Multi-Processing Modules (MPM) and Process/Thread Lifecycle

概念

Apache HTTP Serverにおけるマルチプロセッシングモジュール（MPM）は、ネットワークポートのバインド、リクエストの受け付け、およびそれらを処理する子プロセスやスレッドのライフサイクル管理を担当するコアコンポーネントです。異なるMPM（Event、Worker、Preforkなど）は、それぞれ異なる並行処理モデル（プロセス駆動、ハイブリッドスレッド駆動、イベント駆動など）を実装しています。

なぜ重要か

MPMとプロセス/スレッドのライフサイクル管理は、Webサーバーのパフォーマンス、スケーラビリティ、およびリソース消費効率を決定づけるため極めて重要です。アイドル状態のプロセスやスレッドを適切に維持し、負荷に応じて動的に増減させ、エラー発生時やシャットダウン時に安全にリソースを回収することで、サーバーの安定稼働が保証されます。

関与するモジュール

主要エンティティ

  • **symbol:server/mpm/event/event.c#child_main**: 子プロセスのメイン処理を担当する関数。スレッドの生成（ap_thread_create）やシグナル処理のセットアップ、および終了処理のハンドリングを行います。
  • **symbol:server/mpm/event/event.c#clean_child_exit**: 子プロセスを安全かつクリーンに終了させるための関数。終了コードを受け取り、クリーンアップ処理や終了通知（event_note_child_stopped）を行います。
  • **symbol:server/mpm/event/event.c#perform_idle_server_maintenance**: アイドル状態のサーバープロセス/スレッド数を監視し、必要に応じて新しい子プロセスを生成（make_child）したり、不要なプロセスに終了シグナル（ap_mpm_podx_signal）を送信したりするメンテナンス関数。
  • **symbol:server/mpm/event/event.c#set_thread_limit**: 設定ファイルからスレッド数の上限（ThreadLimit）をパースし、コンテキストの検証（ap_check_cmd_context）を行った上で設定するコマンドハンドラ。

エンドツーエンドの流れ

提供されたシンボル情報から推測されるライフサイクルの流れは以下の通りですが、詳細なエンドツーエンドのフロー全体はまだ完全には解析されていません。

1. **設定の適用**: 起動時に set_thread_limit などの設定関数を通じて、スレッド制限などのパラメータが構成されます。 2. **アイドル監視とプロセス生成**: メインループ等から perform_idle_server_maintenance が定期的に呼び出され、稼働中のプロセス数が監視されます。不足している場合は make_child を介して新しい子プロセスが起動されます。 3. **子プロセスの初期化と実行**: 起動した子プロセスは child_main を実行し、リクエストを処理するためのワーカースレッド群を生成・管理します。 4. **プロセスの終了**: エラーの発生やサーバーの再起動・停止命令に伴い、clean_child_exit が呼び出され、子プロセスは安全にリソースを解放して終了します。

重要な不変条件

現時点では、プロセスやスレッドの生成・破棄時における同期プリミティブや、スコアボードの整合性に関する重要な不変条件は完全には解析されていません。

よくある落とし穴

現時点では、各MPMにおけるシグナルハンドリングの競合や、スレッド制限（ThreadLimit）の動的変更に関する制約など、具体的な実装に起因するよくある落とし穴の詳細は未解明です。
