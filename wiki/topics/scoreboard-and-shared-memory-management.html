Scoreboard and Shared Memory Management

概念

**Scoreboard and Shared Memory Management**（スコアボードおよび共有メモリ管理）は、Apache HTTP Serverにおいて、親プロセスと子ワーカープロセス（またはスレッド）間で実行状態や統計情報を共有するための仕組みです。マルチプロセスモデルにおいて、各ワーカーの稼働状態、アクティブな接続、処理中のリクエストなどのステータス情報を一元管理するために、OSの共有メモリ（Shared Memory）が活用されます。

なぜ重要か

Apacheは複数のプロセスやスレッドが並行してリクエストを処理するアーキテクチャを採用しています。親プロセスが各ワーカーの生存状態や負荷を監視し、適切にプロセス数を調整（スケーリング）するためには、オーバーヘッドの少ないリアルタイムな情報共有が不可欠です。また、グレースフルリスタート（Graceful Restart）時に、古い世代のワーカーが既存の接続を安全に処理し終えるのを追跡・調整するためにも、この共有メモリ上のスコアボードが重要な役割を果たします。

関与するモジュール

  • module:include：スコアボードのデータ構造やAPIの定義を提供します。
  • module:server：スコアボードの初期化、共有メモリの確保、および更新処理の実装を担当します。

主要エンティティ

本機能は主に以下のファイルと、その中で定義されるデータ構造によって構成されています。

  • **include/scoreboard.h**
  • スコアボード全体のレイアウトを定義するヘッダーファイル。
  • global_score（サーバー全体の統計や世代情報）、process_score（子プロセスの状態）、worker_score（個々のスレッド/ワーカーの状態）などの構造体が定義されています。
  • **server/scoreboard.c**
  • 共有メモリ領域の作成、アタッチ、初期化、およびスコアボードの更新を行うAPIの実装ファイル。

エンドツーエンドの流れ

親プロセスと子ワーカー間での一般的な連携フローは以下の通りですが、具体的なAPI呼び出しの全容や排他制御のライフサイクルは、現時点の解析範囲では完全には特定されていません。

1. **初期化**: 親プロセスの起動時に、server/scoreboard.c の関数を通じて必要なサイズの共有メモリ領域が確保され、スコアボード構造体が初期化されます。 2. **アタッチ**: 子プロセス（ワーカー）がフォークまたは生成された際、この共有メモリ領域にアタッチし、自身のスロット（worker_score）へのポインタを取得します。 3. **状態更新**: 各ワーカーは、接続の受け入れ、リクエストの読み込み、レスポンスの送信、キープアライブ状態への移行など、状態が変化するたびに自身のスコアボード情報を更新します。 4. **監視と制御**: 親プロセスやステータス表示モジュール（mod_status など）は、この共有メモリを読み取ることで、システム全体の稼働状況をリアルタイムに把握します。

重要な不変条件

  • **構造の一貫性**: 親プロセスとすべての子プロセス間で、スコアボードのメモリレイアウト（構造体のサイズやアライメント）が完全に一致している必要があります。
  • **排他的な書き込み**: 各ワーカープロセス/スレッドは、自身に割り当てられた特定の worker_score スロットのみを更新し、他のワーカーの領域を破壊してはなりません。
  • *注意*: 具体的なアサーションや、コードレベルで強制される不変条件の詳細は、現時点では未検証です。

よくある落とし穴

  • **共有メモリのクリーンアップ漏れ**: プロセスが異常終了した際、OS上に共有メモリセグメントが残存し、再起動時にリソース不足や競合を引き起こす可能性があります。
  • **プラットフォーム依存性**: 共有メモリの実装（POSIX、System V、匿名マップなど）はOSに依存するため、ポータビリティの確保に注意が必要です。
  • **シグナルハンドラ内での操作**: シグナルハンドラ内で非同期安全（Async-Signal-Safe）ではないスコアボード操作を行うと、デッドロックやメモリ破損の原因になります。
  • *注意*: 本プロジェクト（httpd-2.4.67）における具体的なバグや特有の落とし穴の詳細は、現時点では特定されていません。

次に読む場所

  • **include/scoreboard.h**: スコアボードを構成する各種構造体（global_score, process_score, worker_score）の定義と、公開APIの宣言を確認してください。
  • **server/scoreboard.c**: 共有メモリの確保ロジックや、スコアボードの初期化・更新処理の具体的な実装コードを確認してください。
