Dynamic Module Loading and Configuration Tree Parsing

概念

Apache HTTP Serverの起動および設定解析フェーズにおいて、設定ファイルの記述に基づいて共有オブジェクト（DSO）を動的にロードし、解析された設定ディレクティブをメモリ上に階層的な「設定ツリー」として構築・管理する仕組みです。これにより、コア機能と動的モジュールが統合され、各モジュールに応じた設定の適用が可能になります。

なぜ重要か

Apacheはコア機能と多数のモジュールから構成されており、必要なモジュールのみを動的にロード（LoadModule）することで、メモリ使用量を最適化し、柔軟な機能拡張を可能にします。また、ロードされたモジュールが提供する多様なディレクティブを正しく解釈し適用するためには、設定ファイルをパースして階層構造（設定ツリー）として保持し、各モジュールに設定を配る仕組みが不可欠です。

関与するモジュール

  • module:include
  • module:modules/core
  • module:server

主要エンティティ

  • **symbol:include/util_cfgtree.h#ap_directive_t**: 設定ファイルをメモリ上に階層構造（設定ツリー）として表現するためのノード構造体です。ディレクティブ名、引数、位置情報（ファイル名・行番号）を保持します。
  • **symbol:modules/core/mod_so.c#load_module**: LoadModule ディレクティブのハンドラとして登録されている関数です。共有オブジェクト（DSO）を動的にロードし、Apacheのグローバルモジュールリストへ統合します。
  • **symbol:server/config.c#create_server_config**: サーバー設定ベクター（ap_conf_vector_t）を作成する内部関数です。

エンドツーエンドの流れ

提供された情報からは、動的モジュールロードと設定ツリー解析の完全なエンドツーエンドの統合フロー（どのタイミングで create_server_config が呼ばれ、どのように ap_directive_t のツリー構築と load_module が相互に作用するか）の全容は完全には明らかになっていません。

現時点で判明している部分的な流れは以下の通りです：

1. **設定ファイルの解析とツリー構築**: 設定ファイルの解析中、新しいディレクティブが検出されるたびに ap_directive_t 構造体のノードが生成され、ap_add_node() を通じて設定ツリー（ルートは ap_conftree）に挿入されます。 2. **動的モジュールのロード**: 設定ファイル内で LoadModule ディレクティブが検出されると、load_module が呼び出されます。

  • 既にロード済みのモジュールや静的リンク済みモジュールとの重複チェックを行います。
  • dso_load を呼び出し、指定されたファイルをプロセス空間にマッピングします。
  • apr_dso_sym を使用して、共有オブジェクトからモジュール構造体（module）を取得します。
  • モジュールの magic フィールドが MODULE_MAGIC_COOKIE と一致するか検証します。
  • ap_add_loaded_module を呼び出し、Apacheのグローバルモジュールリストへ追加します。
  • ap_single_module_configure を呼び出し、モジュールの設定を初期化します。

    • 3. **サーバー設定の作成**: サーバー設定の初期化フェーズ（init_server_config など）において、create_server_config が呼び出され、設定ベクターが生成されます。

重要な不変条件

  • **モジュールの重複防止**: ロード対象のモジュールが既にロードされておらず、かつ静的リンクされたモジュールと重複していない必要があります（load_module 内で検証）。
  • **モジュールの有効性**: ロードされたDSOが MODULE_MAGIC_COOKIE を保持する有効なApacheモジュール構造体（module）である必要があります。
  • **設定ツリーの順序維持**: ap_directive_t は設定ファイルに記述された順序を保持します。ただし、閉じタグ（例: </Directory>）はツリー内のノードとしては保存されません。
  • **メモリ管理**: load_module は cmd->pool（通常は pconf）を使用してメモリを管理しており、サーバーの再起動時に自動的にクリーンアップされます。

よくある落とし穴

  • **バージョン不整合**: DSOの magic 番号がサーバー本体の MODULE_MAGIC_COOKIE と一致しない場合、互換性エラーとしてロードが失敗します。
  • **シンボル解決の失敗**: 指定されたモジュール名に対応するシンボルが共有オブジェクト内に存在しない場合、ロードエラーとなります。
  • **設定ツリーの last ポインタ**: ap_directive_t の last メンバはツリー末尾へのアクセスを高速化するためのショートカットですが、常に最新であるとは限りません。
